## 背景與目標

彰化基督教醫院電子採購平台的後台，讓院內承辦審核廠商會員、招標、詢價與醫材。規格來自 SA／SD 文件，欄位與錯誤訊息差一個字驗收就不會過。

為了讓實作緊貼規格，開發採 contract-first：先依 SD 寫好 API 契約與資料驗證，mock 用同一份契約，最後才做頁面。規格之間互相衝突時，先記錄裁定結果再修正，不在程式裡各自猜。

2026-05 從 demo 與設計系統開始參與，接著做共用表單、醫材審核，再接手系統設定。

## 核心功能

- **設計系統與共用表單**：字級、按鈕、輸入框與深色模式，以及檔案上傳、浮動標籤、失焦驗證、富文字編輯器
- **醫材審核**：經辦申請審核與員工審核，含指派醫生、結案、批次審核
- **系統設定**：會費方案、檔案範本、權益聲明、首頁輪播（上傳後裁切與預覽）
- **分頁保活**：切換分頁再回來時，表單輸入仍在

## 技術架構

- **前端**：Nuxt 4 SPA，Tailwind CSS
- **API 契約**：oRPC + Zod 依業務切分，MSW mock 使用同一份契約；回傳資料與 schema 不符時只告警、不中斷畫面
- **資料層**：Pinia Colada 管理查詢與更新
- **品質**：oxlint、ESLint、Stylelint、cspell、Vitest、Playwright；以 git hash 偵測使用者停留在舊版部署
- **規格流程**：規格衝突寫成決策紀錄，頁面以 OpenSpec 對照 SA 與 Figma 的差異逐條收斂

## 挑戰與解法

- **契約不能只留當頁欄位**：同一支 API 被多頁共用，只留當頁用到的欄位，下一頁就會缺資料。契約改為對齊完整的 SD，條件必填在 schema 設為選填，由畫面再檢查。
- **未儲存離開與分頁保活互相干擾**：輪播詳情頁自訂離開提示後，切走再回來表單會被重新載入。改回全站共用的離開確認，並把詳情頁加進保活清單，與招標詳情用同一套做法。
- **錯誤提示方式不一致**：規格要求列表操作失敗時跳系統訊息、關閉後重新查詢，原本卻用 toast。列表頁改用可等待關閉的訊息框；詳情頁不需要等使用者關閉，沿用全站的系統訊息對話框。
