## 背景與目標

臺灣銀行官網的內部 CMS，內容發布到[官網前台](/works/bot-frontend)。行員在後台上稿 Banner、活動、FAQ、服務據點、新聞稿等內容，經過草稿 → 送審 → 審核 → 放行才會上線。

官網頁面分兩類：首頁模組（一二層）與內頁（三四層）。專案從 Angular 11 一路升級到 17，模組多、層級深，前後台的檔案網域也分開。

2026-09 加入後，主要負責讓首頁模組也能上稿頁籤選單，並修正富文字編輯器與檔案上傳的問題。

## 核心功能

- **首頁模組的頁籤選單**：操作方式與內頁一致，行員不用學新介面
- **審核預覽**：審核端沿用同一套表單，切成唯讀模式即可預覽
- **富文字雙網域**：後台編輯時以 CMS 網址顯示圖片，存檔時轉回前台網址
- **連結切換保留內容**：從「編輯內容」切到「連結網址」再切回來，原本的內容仍在

## 技術架構

- **前端**：Angular 17，功能模組 lazy load；UI 以 Bootstrap 為主，富文字使用 SunEditor
- **共用模組**：頁籤選單只依賴抽象的 API service，首頁模組、內頁與審核端透過 Angular DI 各自注入實作
- **上稿流程**：草稿到放行共用同一套表單元件，以模式切換可編輯狀態

## 挑戰與解法

- **內頁元件要給首頁模組用**：兩邊畫面相同、API 不同。複製一份再改 API 會讓之後的修正要做兩次，因此把 API 呼叫抽成可替換的 service，首頁模組與審核端各自注入，既有內頁的程式不需要改動。
- **前後台檔案網域不同**：HTML 裡存的是前台網址，後台載入時圖片破圖。改為載入時把前台網址換成 CMS 網址，存檔前再換回來，資料庫裡永遠只存前台網址。
- **資料遺失與誤蓋**：編輯器停在原始碼模式時存檔會拿到空內容、同名檔案確認覆蓋後實際沒蓋掉、表單調整層級後檔案掛錯位置，逐一補上對應的狀態切換與參數。
